# 忘却曲線カレンダー 仕様書

> そのメモ、もちろん忘れます

## 1. コンセプト

その日書いたメモを、忘却曲線に沿って未来の日付に自動配置し、
「思い出し直すタスク」としてカレンダー上に積み上げていくメモ帳。

- メモを書く → 忘却曲線に沿った復習日が自動生成される
- カレンダーを開く → その日に思い出し直すべき過去のメモが積み上がっている
- 思い出せたか否かを記録する → 残りの復習日が自動で再スケジュールされる

## 2. 対象環境

- 静的サイト（ビルド不要）。GitHub Pages で公開。
- スマートフォン / タブレット / PC の全レスポンシブ対応。
- データはブラウザの `localStorage` に保存（端末内で完結。サーバ送信なし）。
- モダンブラウザ（ES Modules / CSS custom properties 対応）。

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| メモ (Note) | ユーザーが書いた本文。復習スケジュールの発生源。 |
| 追加メモ (Child Note) | 既存メモに紐付けて書くメモ。独立した忘却曲線を持つ。 |
| 復習 (Review) | ある日付に発生する「思い出し直すタスク」。 |
| ステップ (Step) | 復習が忘却曲線の何番目かを表す 0 始まりのインデックス。 |
| 定着 (Graduated) | 全ステップを終えた状態。カレンダーから外れる。 |
| 定着度 (Ease) | 記憶の定着しやすさ係数。再スケジュール時の倍率に使う。 |

## 4. データモデル (schema v3)

```jsonc
{
  "schemaVersion": 3,
  "notes": [
    {
      "id": "n_xxxxxxxx",
      "parentId": null,            // 追加メモなら親メモの id
      "title": "",
      "cue": "減価償却の3つの方法は？",  // 思い出すための手掛かり（任意）
      "body": "本文",
      "tags": ["tag1"],
      "anchorDate": "2026-09-17",  // 起点日（通常は作成日）
      "createdAt": "ISO8601",
      "updatedAt": "ISO8601",
      "status": "active",          // active | graduated | archived | inbox（復習なし）
      "color": null,

      // 起点：作成時に決めた曲線と分散。以後変わらない（変更は reschedule イベント）
      "origin": {
        "presetId": "standard",
        "intervals": [1, 3, 7, 14, 30, 60, 120, 240, 480, 960, 1920],
        "spread": 0.12,   // 分散の強さ（0 で分散なし）
        "seed": 4721      // 分散のシード（0-9999、ユーザーが変更可）
      },

      // 出来事：起きたことを順に積む（唯一の真実）
      "events": [
        { "id": "e_x", "type": "rate", "at": "ISO8601", "day": "2026-09-18",
          "reviewKey": "g0", "step": 0, "rating": "known" }
      ],

      // 以下は events から導出されるキャッシュ（保存はするが、読み込み時に再生成する）
      "schedule": { "presetId": "standard", "intervals": [...], "ease": 2.6, "adaptive": true },
      "reviews": [
        { "id": "g1", "step": 1, "due": "2026-09-20", "status": "pending",
          "rating": null, "completedAt": null, "extra": false }
      ]
    }
  ],
  "settings": { /* 5章 */ },
  "meta": { "createdAt": "ISO8601", "updatedAt": "ISO8601", "appVersion": "0.5.1" }
}
```

### 4.1 出来事 (events)

| type | 内容 | 追加フィールド |
| --- | --- | --- |
| `rate` | 想起結果を記録した | `reviewKey`, `step`, `rating` |
| `skip` | その回を飛ばした | `reviewKey`, `step` |
| `postpone` | 予定日をずらした | `reviewKey`, `step`, `due` |
| `restart` | 今日を起点に組み直した | — |
| `reschedule` | 曲線・分散・シードを変えた | `presetId`, `intervals`, `spread`, `seed` |

`reviewKey` は再生中に生成される安定キー（`g0`, `g1`, …）。再生は決定的なので、
同じ出来事からは必ず同じ予定が得られる。

復習はメモに内包する。これによりメモ単位のエクスポート／削除でスケジュールが破綻しない。
カレンダー描画用の「日付 → 復習」インデックスは読み込み時にメモリ上で構築する。

## 5. 設定項目

| キー | 既定値 | 内容 |
| --- | --- | --- |
| `theme` | `system` | `system` / `light` / `dark` |
| `presetId` | `standard` | 既定の忘却曲線プリセット |
| `customIntervals` | `[1,3,7,14,30,60]` | `custom` プリセットの間隔（日） |
| `adaptive` | `true` | 想起結果に応じた再スケジュールを行う（既存メモにも適用） |
| `hideBodyUntilRecall` | `true` | 復習時は手掛かりだけを見せ、操作して本文を開く |
| `spreadId` | `normal` | 復習日の分散の強さ（none / small / normal / large） |
| `weekStart` | `0` | 週の開始曜日（0=日曜 / 1=月曜） |
| `carryOverOverdue` | `true` | 期限超過の復習を「今日」に繰り越して表示 |
| `overdueDailyLimit` | `10` | 1 日に取り戻す期限切れの上限（0 = すべて）。その日に取り戻した数を差し引くので補充されない |
| `showCreatedOnCalendar` | `true` | 作成されたメモもカレンダーに表示 |
| `defaultExportFormat` | `markdown` | エクスポートの既定形式 |

## 6. 忘却曲線エンジン

### 6.1 プリセット

| ID | 名称 | 回数 | 最長 |
| --- | --- | --- | --- |
| `none` | あとで決める | 0 | 復習予定を作らない（status = `inbox`） |
| `standard` | 標準 | 11 | 約 5 年 |
| `intensive` | 集中 | 13 | 約 4 年 |
| `light` | ゆるめ | 9 | 約 8 年 |
| `lifelong` | 一生もの | 12 | 約 30 年 |
| `custom` | カスタム | 任意 | 最大 100 年 |

間隔は「日数」で持ち、遠い先ほど大きく開く（例: 標準は 1, 3, 7, 14, 30, 60, 120,
240, 480, 960, 1920 日）。年単位まで伸ばしても回数はさほど増えないため、
「いつかまた目に触れる」という感覚を保ったまま長く付き合える。

### 6.2 初期スケジュール生成

メモ作成時、`anchorDate + intervals[i]` 日の位置に step=i の復習を生成する。
つまり作成直後からカレンダーの未来日に復習タスクが並ぶ。

### 6.2.1 復習日の分散（シード）

同じ日に複数のメモを書くと、間隔が同じである以上、未来の復習日もすべて同じ日に重なる。
これを避けるため、メモごとに **シード**（0〜9999）を持たせ、各回の間隔にゆらぎを与える。

```
ずらす量 = round(間隔 × ratio × jitter(seed, step))    jitter ∈ [-1, 1]
```

- `ratio` は設定（none 0 / small 0.06 / normal 0.12 / large 0.22）
- ずらす量は**間隔に比例**するので、翌日（1 日）は四捨五入で 0 になり動かない。
  一方 1 年後（365 日）なら ±44 日、5 年後なら ±8 ヶ月ほど散る
- 並び順は必ず保つ（前の回より最低 1 日あと）
- 同じシードなら常に同じ結果（再生の決定性を壊さない）
- シードはユーザーが編集画面で変更でき、変更は `reschedule` イベントとして記録される
  （完了済みの履歴は保たれ、未来の予定だけが組み直される）

`origin.intervals` はプリセットそのままの値を保持し、分散を適用した実効間隔は
再生時に導出する。プリセットの表示は常にきれいな数字のままになる。

### 6.3 想起結果による再スケジュール（`adaptive` が有効な場合）

| 評価 | ease 変化 | 挙動 |
| --- | --- | --- |
| 覚えていた (`known`) | +0.10 | 次のステップへ進む |
| あいまい (`vague`) | -0.10 | 同ステップの追加復習を短い間隔で 1 回挿入してから次へ |
| 忘れた (`forgot`) | -0.25 | ステップ 0 から組み直す（完了日を新たな起点とする） |

- `adaptive` が無効な場合は想起結果を記録するだけで、作成時に決めた予定日は動かさない。
- `ease` は 1.3 〜 3.0 でクランプ。
- 倍率 `factor = ease / 2.5`。
- 未完了の復習 `j` の新しい期限は `完了日 + max(1, round((intervals[j] - intervals[i]) * factor))`。
- 全ステップ完了で `status = "graduated"`。「もう一周」で再開できる。

### 6.4 期限超過（思い出し待ち）

期限を過ぎた `pending` 復習は「思い出し待ち」として扱う。

- カレンダー上の日付自体は変更しない（履歴を壊さない）。
- `carryOverOverdue` が有効なら「今日」のキューへ繰り越す。
- 同じメモが何回分もたまっている場合は、いちばん古い 1 件だけをキューに出す
  （1 件記録すれば残りは自動で組み直されるため）。
- `overdueDailyLimit` 件までに絞り、残りは順番待ちとして保つ。
  「未達」「失敗」ではなく「思い出し待ち」と表示し、負債感を持たせない。

### 6.4.1 今日はここまで

`overdueDailyLimit` は「その日に取り戻した件数」を差し引いて数える。
こなしても次が補充されないため、「今日はこの件数だけで大丈夫」という約束が守られる。
追加でやりたいときは、本人が「もう少しやる」を押したときだけ上限を超えて出す。
今日カード・日別パネル・まとめて復習は、すべて同じ `todayQueue()` を見る。

### 6.5 取り消し

想起の記録は `events` の追加なので、取り消しは「最後の出来事を取り除いて再生し直す」
だけで済む。`ease` も未来の予定も記録前の状態に正確に戻る。
取り消せるのは常に最後の出来事のみ（履歴の途中を書き換えない）。

## 7. 画面構成

| ルート | 画面 | 内容 |
| --- | --- | --- |
| `#/calendar` | カレンダー | 月表示。日セルに復習件数・新規メモ数を表示。日を選ぶと詳細パネル。 |
| `#/notes` | メモ一覧 | 検索・タグ絞り込み・並び替え。選ぶと編集画面へ。 |
| `#/note/<id>` | メモ編集 | 全画面のテキストエディタ。`?from=` に戻り先、`?parent=` `?date=` で新規作成。 |
| `#/stats` | 記録 | 連続日数、想起の内訳、16 週間のヒートマップ、今後 12 ヶ月の予定、タグ別。 |
| `#/settings` | 設定 | 表示・曲線・データ管理（エクスポート／バックアップ／復元／全消去）。 |
| `#/help` | ヘルプ | 使い方、忘却曲線の説明、バージョン情報、GitHub リンク。 |

補助 UI

- **今日カード** — カレンダー上部。今日の件数・思い出し待ち・［思い出し始める］
- **集中復習モード** — 全画面。手掛かり → ［内容を見る］ → 想起結果 → 次へ → 完了サマリ
- **年月ピッカー** — 年月表示をタップ。年の増減 + 12 か月グリッド（月ごとの復習件数付き）
- メモエディタ（ダイアログ／モバイルは全画面）
- 日別パネル（PC はサイドパネル、モバイルはボトムシート）
- トースト通知、確認ダイアログ

### 7.1 復習の流れ（v0.2 の中心）

「読んで自己評価」ではなく「思い出してから答え合わせ」にする。

```
手掛かり（cue またはタイトル）を見る
   ↓  頭の中で思い出す
［内容を見る］
   ↓  本文が開く
［覚えていた / あいまい / 忘れた］
   ↓
次の復習日が決まる
```

`hideBodyUntilRecall` を切ると、従来どおり最初から本文を表示する。

| 対象 | 形式 |
| --- | --- |

## 9. 拡張性のための設計方針

1. **ストレージ抽象化** — `StorageAdapter` インタフェース（すべて非同期の `load` / `save` / `clear`）
   越しに読み書きする。IndexedDB やクラウド同期はアダプタ差し替えで対応できる。
   保存できない環境（プライベートモード等）は `persistent: false` を返し、UI が警告を出す。
2. **スキーマバージョン管理** — `schemaVersion` とマイグレーション関数チェーンを用意。
3. **出来事ベースのスケジューラ** — 予定は `origin + events` の再生結果。
   アルゴリズム追加（SM-2 / FSRS など）は `replay()` の分岐を差し替えるだけでよく、
   過去の記録を作り直す必要がない。取り消し・統計・将来の同期も出来事列から導ける。
4. **状態の一元管理** — `core/store.js` が単一の真実の源。UI は購読して再描画する。
5. **ビルドレス ES Modules** — 依存ゼロ。必要になった時点でバンドラを導入できる構成に留める。
6. **図は色だけに頼らない** — 想起結果の 3 色は、色覚特性を含む見分けやすさを数値検証した
   組み合わせを使い、凡例と数値ラベルを必ず添える。件数の濃淡は単一色相の連続スケール。

## 8.1 メモ編集画面（v0.5）

メモを選ぶと、アプリの表示領域すべてを使う編集画面に入る。

```
┌────────────────────────────┐
│ ← タイトル      ↶ ↷ 🔍 ⓘ ⋮ │ ツールバー
├────────────────────────────┤
│                            │
│   本文（残りの高さすべて）    │ 内部スクロール
│                            │
├────────────────────────────┤
│ リスト チェック 完了 字下げ … │ ショートカットバー
├────────────────────────────┤
│ 保存済み            12字・3行 │ ステータスバー
└────────────────────────────┘
```

### 責務の分け方

| 層 | ファイル | 責務 |
| --- | --- | --- |
| 履歴 | `editor/history.js` | 元に戻す・やり直す（本文と選択範囲の組） |
| 中核 | `editor/textEditor.js` | 本文・選択範囲・行操作・コマンド登録 |
| 画面 | `ui/views/noteEditor.js` | ツールバー・保存・検索置換・メモ情報 |
| 保存 | `core/store.js` | 本文の保存と復習予定は別の操作として扱う |

編集機能はすべて **コマンド** として登録する。ツールバー・ショートカットバー・
キーボードのどれからでも `editor.run('bullet')` のように同じ処理を呼ぶ。
機能を足すときは `registerCommand()` で 1 つ増やすだけで、
エディタ本体や保存処理は書き換えない。

### ソフトキーボードへの追従

スマホでキーボードが出ると、画面の下側が隠れる。縮むのは「実際に見えている領域
(visualViewport)」で、`100dvh` などのレイアウト高さは変わらないため、
そのままでは下端のバーがキーボードの裏に回る。

- `ui/viewport.js` が visualViewport を監視し、CSS 変数へ流し込む
  （`--fcc-vv-height` / `--fcc-vv-top` / `--fcc-keyboard`、`data-keyboard="open"`）
- 編集画面は `position: fixed` + `height: var(--fcc-vv-height)` + `top: var(--fcc-vv-top)`
  で、見えている領域にぴったり収まる
- `interactive-widget=resizes-content`（viewport meta）で、対応ブラウザでは
  レイアウト自体も縮める
- キーボードが出ている間は下端の余白（ホームバー分）を詰める
- 領域が縮んだら、入力中の行が隠れないようカーソル位置へ寄せ直す

ショートカットバーは、狭い画面では文字を省いてアイコンだけにし、
横スクロールなしで全部が収まるようにする（幅 520px 以上で文字も表示）。

### 決めごと

- 本文の自動保存は入力の 700ms 後。`Ctrl/⌘+S` で即時保存
- 新規メモの id は最初の保存で一度だけ確保する（再試行で増やさない）
- 本文が空のまま閉じても、メモは作らない
- 日本語入力の変換中は履歴を刻まない（確定で 1 手）
- 一括置換は 1 手として戻せる
- 本文の前後の空白・改行は保存時に削らない
- 本文の編集では復習の予定・起点日を変更しない
- メモごとにカーソル位置とスクロール位置を覚える

## 9.1 書きかけの保護と保存の確実さ

| 課題 | 対応 |
| --- | --- |
| 入力中に閉じると消える | 入力のたびに下書きを `localStorage` へ保存（本体データとは別キー）。開くと復元し、「破棄」でのみ消える |
| 保存できたか分からない | `persist()` が成否を返し、エディタは `flush()` の成功を待ってから閉じる。失敗時は本文を保持して再試行・コピーを出す |
| 複数タブで上書き | 保存ごとに `meta.saveToken` を書き、保存前に他タブの書き込みを検出して取り込んでから書く。`storage` イベントでも取り込む |
| 統合で本文が消える | メモを丸ごと入れ替えず、**出来事は和集合・中身は `contentUpdatedAt` の新しい方**で統合する |
| 削除が復活する | `deleted`（墓標）を持ち、古いタブの保存で復活させない。復元は明示操作のときだけ |
| 保存できない環境 | アダプタが `persistent: false` を返し、画面上部に警告を出す |

統合の規則:

1. **出来事 (events)** — id の和集合。復習の記録は足し算なので失われない
2. **中身 (body / title / cue / tags)** — `contentUpdatedAt` が新しい方を採用。
   本文が食い違った場合、古い方は `conflicts` に退避し、編集画面で確認できる
3. **削除** — `deleted[id]` が相手のメモの更新時刻より新しければ、そのメモは復活させない

どちらのタブで書いた内容も、黙って失われないことを優先する。

## 10. テスト

コアロジック（`assets/js/core/`）は DOM 非依存の純 JavaScript なので、Node の標準テストランナーで検証する。

```bash
npm test   # node --test tests/core.test.mjs
```

UI を含む動作確認はブラウザで行う（`npm run serve`）。
